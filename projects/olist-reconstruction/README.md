# Olist reconstruction — reproducible source

**What this is:** independent, aggregate-only reconstruction of the recovered MSc team-project data. It is **not** the original assessed Power BI PBIX, report pages or DAX. The cleaned workbook and all row-level customer/order/seller IDs are intentionally excluded from GitHub.

The public dashboard reads `lib/olist-reconstruction-data.ts`. That file is generated by `rebuild.py`, not hand-authored.

## Run with the recovered workbook

Requires Python 3.10+ and its standard library only, plus your **private** copy of `Olist Dataset Clean v3.xlsx`.

From the repository root:

```bash
python3 projects/olist-reconstruction/rebuild.py "/path/to/Olist Dataset Clean v3.xlsx" --check
python3 -m unittest discover -s projects/olist-reconstruction/tests -v
```

`--check` recomputes the figures from all eight recovered sheets and fails if the committed dashboard data differ, **without changing files**. To intentionally regenerate and review them:

```bash
python3 projects/olist-reconstruction/rebuild.py "/path/to/Olist Dataset Clean v3.xlsx"
git diff -- lib/olist-reconstruction-data.ts
npm run check
```

The script uses streaming Python-standard-library OOXML parsing because the recovered workbook is large. It expects this workbook’s original sheet order, inline-string encoding and column names, and **fails rather than silently accepting an incompatible workbook**. Temporary intermediate aggregates are removed automatically. Never commit the workbook or the intermediate JSON.

## What is independently checked

- 98,582 distinct order IDs; 110,929 item rows; 97,334 reviewed orders.
- 96,394 delivered orders, of which 96,386 have the two dates needed for the late-delivery comparison; 7,824 were delivered strictly after the estimated date.
- 97,193 orders with items and 1,389 without item rows.
- 13,401,483.41 in listed item prices. **Do not call it payment, actual revenue or profit.**
- Month/category/customer-state totals reconcile, including 2017/2018, eight individually displayed categories plus Other, and the ten displayed customer states plus Other.

Customer geography is joined by the unique customer key. Product category is joined by product key and the recovered translation lookup. The 50,000-row geolocation sheet has repeated ZIP prefixes and is **not joined directly** into order totals. The missing ninth table in the original MSc case is still unverified. Sparse 2016 and September 2018 edge months are not full comparable trading periods.
